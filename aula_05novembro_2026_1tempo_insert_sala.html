Central de Avisos — INSERT e cadastro persistente

Aula digital de estudo e simulação no papel. Não exige computador nem login. Objetivos: diferenciar memória e persistência, explicar o INSERT, identificar campos e interpretar sucesso ou falha na gravação.

1. Problema inicial

Se o programa armazena avisos somente em avisos=[], os registros dessa lista comum desaparecem após o processo encerrar. Uma reunião marcada para a semana seguinte precisa continuar disponível. Persistir é gravar em armazenamento que continua existindo após encerrar o Python.

2. Entendendo a tabela

idtitulodatatipo
1Reunião2026-11-10evento

Uma tabela reúne registros; cada campo é uma coluna e cada registro é uma linha. O esquema real da tabela deve permitir os campos enviados.

3. Código comentado para LEITURA

dados = {
    "titulo": "Reunião",
    "data": "2026-11-10",
    "tipo": "evento"
}

# É necessário configurar antes o cliente, as permissões
# e uma tabela 'avisos' compatível. Aqui só interpretamos.
resposta = supabase.table("avisos").insert(dados).execute()

dados: valores que queremos inserir; table("avisos"): destino; insert(dados): solicitação de inclusão de nova linha; execute(): envia a operação. A operação pode falhar por rede, permissão, restrições ou campos inválidos. Fazer a chamada não prova sozinho que houve gravação.

4. Atividade em dupla, sem computador

Regra de validação: título obrigatório; data em AAAA-MM-DD; tipo igual a evento ou avaliacao.

Desenhe uma tabela vazia, analise as tentativas e marque ENVIA ou BLOQUEIA, justificando:

  1. Reunião / 2026-11-10 / evento
  2. [título vazio] / 2026-11-11 / evento
  3. Prova / 2026-11-12 / avaliacao

Se o banco confirmar as inserções válidas, quantos registros existem? O que acontece ao fechar o Python?

5. Verificação individual

  1. Explique uma diferença entre dados em memória e dados persistentes.
  2. Identifique no código tabela, operação, dicionário e envio.
  3. Por que o título vazio deve ser bloqueado?
  4. Um erro de conexão garante que houve gravação? Por quê?
  5. Como confirmar posteriormente os registros armazenados?

Resumo para copiar

PERSISTÊNCIA: dados sobrevivem ao fechamento do programa. INSERT: solicita um novo registro. FLUXO: receber → validar → enviar → verificar resposta. PRÓXIMA ETAPA: SELECT para consultar os registros.
